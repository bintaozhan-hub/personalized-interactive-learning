# 知识咨询 · Knowledge Consultation

结合用户档案（`user_wiki/`）和已沉淀的知识库（`book_wiki/`、`research_wiki/`、`course_wiki/`），为用户的具体问题提供个性化、可执行的建议。

**本 skill 是纯读取型 skill**——检索已有知识，转化输出建议，不创建新文件。

---

# Part A：核心原则

1. **转化而非摘录** — 知识库内容必须根据用户的具体情况转化，而非直接粘贴原文
2. **约束优先** — 用户的当下状态、资源限制、思维框架是建议的边界条件
3. **可用性判断** — 如果知识库内容不适用，不强行引用；诚实说明原因，基于通用知识给出建议
4. **全覆盖检索** — 同时检索书、研究、课程三个知识库，不遗漏任何相关知识

---

# Part B：执行流程

## B.1 Step 1 — 理解问题本质

用一句话重述用户问题的核心，并识别问题类型：

| 问题类型 | 特征 | 示例 |
|----------|------|------|
| **认知困惑** | 不理解某个概念或原理 | "什么是飞轮效应？" |
| **决策困惑** | 知道选项但不知道选哪个 | "我该做A还是做B？" |
| **执行障碍** | 知道该做但做不到 | "我知道要复盘但我就是不做" |
| **方向迷茫** | 不知道该往哪里走 | "我想做一个AI产品但不知道从哪里开始" |

**输出**：
```
## 问题理解
{问题类型} — {用一句话重述问题核心}
```

---

## B.2 Step 2 — 读取用户上下文

从 `wiki/user_wiki/` 中读取与问题相关的维度，理解用户是谁、怎么思考、当下状态如何。

### 必读维度

- **07_当下状态与近期事件/** — 影响当前决策的临时因素（近期目标、压力、时间节点）
- **03_底层思维模式/** — 用户的推理框架和认知风格（决定了建议用什么方式表达）

### 按需读取维度

| 维度 | 何时读取 |
|------|----------|
| 01_身份与角色/ | 问题涉及职业选择、技能发展 |
| 02_价值观与信念/ | 问题涉及价值判断、取舍 |
| 04_技能与特长/ | 问题涉及能力边界、学习路径 |
| 05_人际关系网络/ | 问题涉及人际互动、沟通 |
| 06_人生重大轨迹/ | 问题涉及过去经历、模式识别 |

### 输出格式

```markdown
## 用户上下文分析

### 当下状态
{从"07_当下状态与近期事件"中提取的相关信息}

### 思维框架
{从"03_底层思维模式"中提取的相关信息}

### 其他相关信息
- 身份与角色：{信息 / 暂无记录}
- 价值观与信念：{信息 / 暂无记录}
- ...

### 关键约束
{从上述信息中提炼出的、会影响建议的约束条件}
例如："资源有限、时间紧迫、对失败敏感、偏好实用主义推理"
```

---

## B.3 Step 3 — 检索知识库

**这是本 skill 的核心步骤**。同时检索三个知识库，找到与用户问题相关的已学知识。

### 3.1 检索 book_wiki（书籍阅读记录）

1. 先读 `wiki/book_wiki/index.md`，识别可能相关的书籍
2. 读取相关书籍的 `《书名》.md`（含阅读蓝图 + 核心收获）
3. 读取相关的部分笔记文件（`第X部分-XXX.md`），提取关键概念和应用记录
4. 重点关注：用户自己写的"我的应用"和"苏格拉底诘问记录"——这些是用户已经内化的内容

### 3.2 检索 research_wiki（行业/概念研究）

1. 扫描 `wiki/research_wiki/` 下的子目录，识别与问题相关的主题
2. 读取相关主题的 `PROGRESS.md`，查看已掌握的概念和术语
3. 读取相关的课程文件（`lessons/000N-xxx.md`），提取可应用的知识
4. 重点关注：🟢 标记的已掌握概念、用户回答中展现的理解深度

### 3.3 检索 course_wiki（课程学习记录）

1. 扫描 `wiki/course_wiki/` 下的子目录，识别与问题相关的课程
2. 读取相关课程的 `PROGRESS.md`，查看已掌握的概念和术语
3. 读取相关的课程文件（`lessons/000N-xxx.md`），提取可应用的知识
4. 重点关注：与用户行业/工作直接相关的课程内容

### 3.4 输出格式

```markdown
## 知识库匹配

### 📚 书籍知识
#### 《书名》第X部分 — {核心问题}
{相关内容摘要——用户当时的关键收获和应用记录}

#### 《书名》第Y部分 — {核心问题}
{相关内容摘要}

*（如无相关书籍知识，标注：暂无相关书籍记录）*

### 🔬 研究知识
#### {研究主题}
{从 PROGRESS.md 或课程文件中提取的相关内容}

*（如无相关研究知识，标注：暂无相关研究记录）*

### 📖 课程知识
#### {课程名}
{从 PROGRESS.md 或课程文件中提取的相关内容}

*（如无相关课程知识，标注：暂无相关课程记录）*

### 可用性判断
{这些内容是否真的能解决用户的问题？}
- 如果可用：说明为什么适用
- 如果部分可用：说明哪些可用、哪些需要调整
- 如果不可用：说明原因，不强行引用
```

### 3.5 检索原则

- **用户自己的理解优先**：优先引用用户笔记中自己的表述，而非知识库的原文
- **不强行匹配**：如果某个知识库没有相关内容，简明标注"暂无"，不编造
- **质量 > 数量**：找到 1-2 个高度相关的内容比列出 5 个勉强相关的更有价值
- **关联度标注**：明确说明每个知识片段与用户问题的关联点

## B.4 Step 4 — 内部反思（不输出给用户）

在给出建议之前，先回答以下四个问题：

1. **这个建议是否考虑了用户的当下状态？**
   - 用户现在有时间吗？有精力吗？有紧迫的时间节点吗？
2. **这个建议是否符合用户的思维框架？**
   - 用户是实用主义还是系统思维？偏好数据还是直觉？
3. **这个建议是否在用户的能力和资源范围内？**
   - 用户有相关的技能吗？有足够的资源吗？
4. **如果我是这个用户，我会觉得这个建议有用吗？**
   - 这个建议是否具体可执行？还是空洞的"你应该多思考"？

**如果任何一个问题的答案是"否"，重新调整建议。**

---

## B.5 Step 5 — 输出转化后的建议

根据用户约束和思维框架，给出具体可执行的建议。

### 转化规则

根据用户在"底层思维模式"中的推理风格，调整建议的表达方式：

| 用户思维风格 | 建议怎么给 |
|-------------|-----------|
| 实用主义推理 | 用具体场景和案例说话，少讲理论；给步骤、给时间节点 |
| 系统思维 | 可以讲框架和全局视角；先说为什么，再说怎么做 |
| 数据驱动 | 给出可量化的指标和验证方式；"试一周后看XX指标是否改善" |
| 直觉/感性 | 用故事和类比；先共情再建议 |

根据用户在"当下状态"中的情况，调整建议的颗粒度：

| 用户当下状态 | 建议怎么给 |
|-------------|-----------|
| 焦虑/疲惫 | 优先给短期可见效的建议；拆分到最小可执行步骤 |
| 资源有限 | 避免需要大量投入的方案；优先零成本或低成本选项 |
| 时间充裕 | 可以给中长期规划；建议系统性学习路径 |
| 面临 deadline | 给最紧急、最高杠杆的一件事 |

### 输出格式

```markdown
## 建议

{具体可执行的建议内容——步骤、时间节点、预期结果}

### 为什么这样建议
{解释为什么这个建议适合这个用户，而不是通用建议}
{关联到用户上下文分析和知识库匹配中的具体信息}

### 来源标注
- 建议A → 📚 《书名》[[第X部分-XXX]]
- 建议B → 🔬 {研究主题} [[lessons/000N-xxx]]
- 建议C → 📖 {课程名} [[lessons/000N-xxx]]
- 建议D → 💡 基于通用知识（知识库内容不适用/不完整）
```

# Part C：特殊情况处理

### 情况 1：用户档案为空

如果 `wiki/user_wiki/` 中没有足够信息：

> "注意：我对你的了解还不够充分。建议先使用 `life-interviewer` skill 建立用户档案，这样我能给出更符合你情况的建议。
>
> 当前建议基于通用知识，可能不完全适合你的具体情况。"

然后继续给出建议——不要因为档案不全就不给建议。

### 情况 2：所有知识库都没有相关内容

如果三个知识库都检索不到与问题相关的内容：

```markdown
## 知识库匹配

### 📚 书籍知识
暂无相关书籍记录

### 🔬 研究知识
暂无相关研究记录

### 📖 课程知识
暂无相关课程记录

### 可用性判断
当前知识库中没有与这个问题直接相关的内容。

## 建议

{基于通用知识给出建议，不强行引用知识库}

💡 提示：如果你经常遇到这类问题，可以考虑用 `industry-research` skill 系统研究一下这个领域。
```

### 情况 3：问题超出能力范围

如果问题涉及专业领域（医疗诊断、法律诉讼、心理治疗等）：

> "这个问题涉及 {专业领域}，建议咨询专业人士。
>
> 我可以提供的是：{从知识管理、思维框架、决策方法等角度能提供的辅助性建议}。"

**不要越界扮演医生、律师、心理咨询师。**

### 情况 4：知识库内容与用户当前状态冲突

如果知识库中的方法论与用户当下的约束矛盾（如用户时间紧迫但方法论需要长期投入）：

```markdown
### 可用性判断
{方法论名称}通常需要 {时间/资源投入}，但你当前 {约束条件}。不完全适用，需要调整。

## 建议
{给出适配当前约束的简化版或替代方案}
```

# Part D：禁忌行为

### 1. 不要直接粘贴知识库原文

```
❌ "你在《定位》第2部分的笔记中写道：'定位就是在用户心智中占据一个位置'……"（照搬）
✅ 把定位的核心思想转化为针对用户当前问题的具体建议
```

### 2. 不要强行引用不相关的知识

```
❌ 用户问时间管理，硬扯一本讲品牌定位的书
✅ 诚实标注"暂无相关记录"，基于通用知识给出建议
```

### 3. 不要编造用户信息

```
❌ 用户档案中没有"价值观"维度的记录，却写"你重视自由和创新"
✅ 标注"暂无记录"，不猜测
```

### 4. 不要给空洞的建议

```
❌ "你应该多思考一下这个问题"、"建议你深入分析"
✅ "本周内找3个人聊一聊他们遇到的具体困难，记录下来，看看有没有共性的模式"
```

### 5. 不要越界扮演专业人士

```
❌ 用户问抑郁症状 → AI 给出治疗建议
✅ 建议咨询心理医生，同时可以从认知框架角度推荐相关书籍
```

### 6. 不要只检索一个知识库就停止

```
❌ 在 book_wiki 找到了相关内容就不再检索 research_wiki
✅ 三个知识库全部检索后再汇总输出
```

# Part F：完整示例

### 输入

```
/consult 我想做一个AI产品，但不知道从哪里开始
```

### 输出

```markdown
## 问题理解
方向迷茫 — 有想法但缺乏具体的启动路径

## 用户上下文分析

### 当下状态
- 最近在思考AI读书产品的设计（2026-04-24）
- 对系统设计有较强的结构化思维

### 思维框架
- 实用主义推理：倾向于从实际场景出发，而非理论框架
- 重视细节和具体实现

### 其他相关信息
- 身份与角色：暂无记录
- 目标与动机：暂无记录

### 关键约束
偏好具体可执行的步骤，而非宏观理论；需要快速验证想法的可行性

## 知识库匹配

### 📚 书籍知识
#### 《精益创业》第2部分 — 如何验证你的想法？
核心观点：通过最小可行产品（MVP）快速验证假设。用户当时的应用记录：计划用MVP方式验证AI读书产品的核心假设。

#### 《精益创业实战》第1部分 — 从问题出发
核心观点：先找到真实存在的问题，再设计解决方案。用户当时的收获：不要问"这个功能好不好"，要问"用户真的需要这个吗"。

### 🔬 研究知识
#### AI行业研究
从 PROGRESS.md 来看，用户已掌握AI产业链结构、主流商业模式。关键发现：AI读书类产品目前处于早期阶段，竞品较少但用户习惯未形成。

### 📖 课程知识
暂无相关课程记录

### 可用性判断
适用。精益创业的方法论可以直接指导AI产品的启动过程。AI行业研究提供了市场背景，帮助判断切入点。

## 建议

从问题验证开始，而不是直接做产品：

1. **找3-5个潜在用户，问他们具体的痛点**（本周内完成）
   - 不要问"你觉得AI读书助手怎么样"
   - 要问"你上次读书时遇到的最大困难是什么"
   - 记录他们现在是怎么解决的（竞品可能是"手动记笔记"而非其他AI产品）

2. **用最简单的方式验证核心假设**（2周内）
   - 假设：用户真的需要AI辅助读书
   - 验证方式：手动扮演AI，给3个人提供读书辅助服务
   - 观察：他们是否真的用？哪个环节最有价值？愿意为哪个环节付费？

3. **只做最核心的一个功能**（1个月内）
   - 不要一开始就做完整系统
   - 选用户反馈最强烈的那个痛点，做一个能用的版本
   - 基于AI行业研究的判断：目前用户习惯未形成，先用单一功能教育市场

### 为什么这样建议
你的思维方式是"从实际场景出发"，所以建议从真实用户访谈开始，而不是先做技术架构。
你重视细节，所以给出了具体的时间节点和可执行步骤。
你当前没有明确的资源约束记录，但从你设计系统的方式看，你偏好渐进式而非一次性投入，所以建议分阶段验证。
AI行业研究显示这个赛道用户习惯未形成，所以第一步应该是验证需求是否存在，而非直接开发产品。

### 来源标注
- 建议1、2 → 📚 《精益创业实战》[[第1部分-从问题出发]]
- 建议3 → 📚 《精益创业》[[第2部分-验证]]
- 市场判断 → 🔬 AI行业研究 [[PROGRESS]]
```
