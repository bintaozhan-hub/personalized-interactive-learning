# 7 维度知识库系统 · Dimension System

用户个人知识库按 7 个维度组织。以下是每个维度的详细说明。

---

## 维度总览

| 序号 | 维度 | 核心问题 | 存什么 | 更新频率 |
|------|------|----------|--------|----------|
| 01 | 身份与角色 | 我是谁？ | 职业、社会身份、不同场景下的角色 | 低 |
| 02 | 价值观与信念 | 我相信什么？ | 判断标准、优先级、核心信念 | 最低 |
| 03 | 底层思维模式 | 我怎么想问题？ | 认知框架、推理方式、决策习惯 | 最低 |
| 04 | 技能与特长 | 我会什么？ | 硬技能、软技能、爱好特长 | 中 |
| 05 | 人际关系网络 | 我跟谁有关系？ | 重要的人、关系性质 | 中 |
| 06 | 人生重大轨迹 | 我经历过什么？ | 转折点、关键经历、重大决定 | 低 |
| 07 | 当下状态与近期事件 | 我现在怎么样？ | 近期事件、当前目标、情绪状态 | 高 |

---

## 01_身份与角色

### 存什么
用户在不同场景下的身份标签和角色定义。

### 典型内容
- 职业身份：产品经理、自由职业者、创业者、学生
- 社会身份：父亲/母亲、丈夫/妻子、儿子/女儿
- 兴趣身份：跑步爱好者、摄影爱好者、读书会发起人
- 组织身份：某公司合伙人、某社群成员

### 什么不该放这里
- 具体技能（放 04_技能与特长）
- 与特定人物的关系（放 05_人际关系网络）
- 近期状态（放 07_当下状态与近期事件）

### 文件命名
`角色名.md`，例如：`产品经理.md`、`摄影爱好者.md`

### 示例文件内容
```markdown
# 产品经理

## 核心信息

- 目前在某互联网公司担任产品经理，负责 B 端 SaaS 产品
- 入行 5 年，从产品助理做起
- 侧重数据驱动和用户研究

## 相关链接

- [[某互联网公司]]
- [[Python编程]]
- [[2022_转行产品经理]]

## 元信息

- 记录时间：2026-07-13
- 信息来源：对话
```

## 02_价值观与信念

### 存什么
用户做判断时依据的核心标准和信念体系。

### 典型内容
- "我觉得自由比稳定重要"
- "做对用户有价值的事，比赚钱更重要"
- "人不应该为了钱做自己不喜欢的事"
- "家庭永远是第一位的"

### 什么不该放这里
- 具体的人生经历（放 06_人生重大轨迹）
- 职业规划（放 07_当下状态与近期事件）
- 性格描述（放 01_身份与角色）

### 特殊规则：待归纳区
**单次对话不直接建子文件**，先写入总文件的"待归纳区"：

```markdown
# 02_价值观与信念

## 索引

（归纳后的子文件链接）

## 待归纳区

- 2026-07-13: 认为自由比稳定更重要，不喜欢被束缚的工作
- 2026-07-13: 做决策时优先考虑"对用户有没有价值"
```

积累 3 条以上相似判断后，提示用户确认归纳：
> "我发现你多次提到自由比稳定重要，是否可以归纳为一条核心价值观——'自由优先于稳定'？"

用户确认后，新建子文件 `自由优先于稳定.md`，将待归纳区的相关条目移入。

### 文件命名
`信念名称.md`，例如：`长期主义.md`、`用户价值优先.md`、`自由优先于稳定.md`

## 03_底层思维模式

### 存什么
不是用户说了什么结论，而是**怎么推导出结论的**——认知框架、推理方式、决策习惯。

### 典型内容
- "遇到问题习惯先拆解成小问题"
- "做决策时倾向于列出所有选项再逐一排除"
- "习惯从反面思考——如果这件事失败了，最可能的原因是什么"
- "看到新东西第一反应是'这跟我已有的知识怎么关联'"

### 什么不该放这里
- 价值观判断（放 02_价值观与信念）
- 具体技能（放 04_技能与特长）
- 性格特点（放 01_身份与角色）

### 特殊规则：观察记录区
**不直接从用户声称中提取**，而是从推理过程中观察。单次对话写入总文件的"观察记录区"：

```markdown
# 03_底层思维模式

## 索引

（归纳后的子文件链接）

## 观察记录区

- 2026-07-13: 用户讲到自己选工作时，先列出所有 offer 的优劣对比表再做决定——习惯系统性比较决策
- 2026-07-13: 聊到创业失败经历时，用户先分析外部因素再分析自身原因——有从外到内的归因习惯
```

积累足够观察后，归纳为模式并建子文件。

### 提取时机
- 用户描述"我怎么想的"时
- 用户做决策的过程描述
- 用户解释为什么选择 A 而不是 B
- 用户复盘失败/成功经历时的归因方式

### 文件命名
`模式名称.md`，例如：`第一性原理思维.md`、`系统性比较决策.md`、`逆向思考习惯.md`

## 04_技能与特长

### 存什么
用户掌握的硬技能、软技能、以及爱好特长。

### 典型内容
- 硬技能：Python 编程、数据分析、视频剪辑、平面设计
- 软技能：谈判、演讲、团队管理、写作
- 爱好特长：吉他（弹了 3 年）、跑步（跑过 5 次全马）、摄影

### 什么不该放这里
- 职业身份（放 01_身份与角色）
- 技能相关的重大经历（放 06_人生重大轨迹）
- 当前正在学的技能（放 07_当下状态与近期事件）

### 每条技能应包含
- 技能名称
- 掌握程度（入门/熟练/精通）
- 使用场景（工作中用、爱好、偶尔用）
- 学习时间/经验
- 相关经历链接

### 文件命名
`技能名称.md`，例如：`Python编程.md`、`谈判技巧.md`、`吉他.md`

### 示例文件内容
```markdown
# Python 编程

## 核心信息

- 自学 Python 3 年，主要用于数据分析
- 熟练使用 pandas、numpy、matplotlib
- 能独立写爬虫和自动化脚本
- 非科班出身，通过项目实战学习

## 相关链接

- [[2021_开始自学编程]]
- [[数据分析项目经历]]
- [[产品经理]]（工作中用 Python 做数据分析）

## 元信息

- 记录时间：2026-07-13
- 信息来源：对话
```

## 05_人际关系网络

### 存什么
对用户重要的人——家人、朋友、伴侣、同事、导师、合作伙伴等。

### 典型内容
- 家人：父母、兄弟姐妹、配偶、子女
- 朋友：从小到大的好朋友
- 职场：重要的领导、同事、合作伙伴、导师
- 伴侣/前任：重要的感情关系

### 每条人物记录应包含
- 与用户的关系
- 怎么认识的
- 认识多久了
- 对用户的影响/意义
- 相关经历链接

### 文件命名
`人名_关系.md`，例如：`张三_创业伙伴.md`、`李四_大学室友.md`、`王五_前领导.md`

### 示例文件内容
```markdown
# 张三 · 创业伙伴

## 核心信息

- 大学同学，认识 10 年
- 2020 年一起创办某公司，张三是联合创始人
- 张三负责技术，用户负责产品和商务
- 目前仍是密切的合作伙伴和朋友

## 相关链接

- [[2020_创业经历]]
- [[某公司]]
- [[谈判技巧]]

## 元信息

- 记录时间：2026-07-13
- 信息来源：对话
```

## 06_人生重大轨迹

### 存什么
用户人生中的转折点、关键经历、重大决定——那些"如果没有这件事，我就不会是现在的我"的事件。

### 典型内容
- 搬家/转学（如果对用户影响大）
- 高考/升学选择
- 职业转换/转行
- 创业经历
- 重大失败或挫折
- 重要的人际关系变化（结婚、分手、重要的人去世）
- 获得重要成就或认可

### 判断标准
> 这件事对用户的人生轨迹产生了实质性的改变吗？

如果是"日常发生的事"但影响不大 → 放 07_当下状态与近期事件
如果是"过去发生但没有重大影响" → 考虑是否值得单独建文件

### 文件命名
`YYYY_事件名.md`，例如：`2020_创业经历.md`、`2018_从北京搬到深圳.md`、`2022_转行产品经理.md`

### 示例文件内容
```markdown
# 2020 创业经历

## 核心信息

- 2020 年初，与大学同学张三一起创办某公司
- 做 B 端 SaaS 产品，面向中小企业
- 用户负责产品和商务，张三负责技术
- 2022 年因资金链问题关闭
- 用户认为这是目前为止最重要的成长经历

## 相关链接

- [[张三_创业伙伴]]
- [[某公司]]
- [[谈判技巧]]
- [[2022_公司关闭后的反思]]

## 元信息

- 记录时间：2026-07-13
- 信息来源：对话
```

## 07_当下状态与近期事件

### 存什么
3 个月内的动态事件——正在发生的事、近期的目标、当前的情绪状态、正在面临的挑战。

### 典型内容
- 近期目标：这个月要完成什么、今年想达成什么
- 当前状态：最近在忙什么、最近心情怎么样
- 近期事件：最近换了工作、最近搬家了、最近开始学某样东西
- 正在面临的挑战或问题
- 短期计划

### 什么不该放这里
- 超过 3 个月的稳定状态（考虑是否归档到其他维度）
- 重大人生转折（放 06_人生重大轨迹）
- 稳定的人际关系（放 05_人际关系网络）

### 特殊规则：定期归档
事件超过 3 个月后，在总文件中标记为"已归档"，子文件保留。

定期（建议每月）回顾此维度，将过期内容标记归档。

### 文件命名
`YYYYMMDD_事件名.md`，例如：`20260603_开始健身.md`、`20260701_准备跳槽.md`

## 维度边界判断指南

当一条信息可能属于多个维度时，按以下优先级判定：

```
优先级从高到低：
1. 05_人际关系网络  — 只要主角是人，优先归这里
2. 07_当下状态与近期事件 — 只要发生在 3 个月内，优先归这里
3. 06_人生重大轨迹  — 过去的重要转折
4. 04_技能与特长    — 具体可命名的能力
5. 02_价值观与信念  — "我认为...是对的/重要的"
6. 03_底层思维模式  — "我习惯这样想"
7. 01_身份与角色    — 兜底维度
```

### 常见边界案例

| 信息 | 归属 | 理由 |
|------|------|------|
| "我大学学的是计算机" | 06_人生重大轨迹 | 过去的关键经历 |
| "我现在是程序员" | 01_身份与角色 | 当前身份 |
| "我最近在学 Rust" | 07_当下状态与近期事件 | 3 个月内的动态 |
| "我会写代码" | 04_技能与特长 | 已掌握的技能 |
| "写代码让我感到自由" | 02_价值观与信念 | 价值判断 |
| "我学新语言时会先看源码" | 03_底层思维模式 | 学习方式/认知习惯 |
| "我的编程老师张老师" | 05_人际关系网络 | 具体人物 |
