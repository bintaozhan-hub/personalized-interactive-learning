# 沉淀示例集 · Settling Examples

本文档提供完整的信息沉淀执行示例，展示从对话提取到最终归档的全过程。

---

## 示例一：基本流程

### 对话片段

```
AI：高中毕业后呢？大学是怎么选的？
用户：我高考成绩一般，能选的学校不多。最后去了武汉的一所二本，学的市场营销。
      说实话选这个专业没什么特别的原因，就是觉得市场营销应该比较好找工作。
      大学四年过得挺平淡的，没什么特别的。
AI：大学里有没有关系比较好的朋友？
用户：有一个室友，叫小李，跟我关系最好。他也是学市场营销的，我们经常一起打球、一起复习。
      毕业之后他去深圳了，我在武汉，联系就少了。但每年过年还是会发个消息。
AI：小李是什么样的人？
用户：他很开朗，跟我完全相反。他是那种在人群里最活跃的人，我是比较安静的那种。
      但他对我影响挺大的，很多事都是他拉着我去做的。比如参加社团、去面试实习，都是他先去的，我才跟着去的。
```

### 第一、二步：提取信息 + 归类

```
1. 大学在武汉的一所二本，学市场营销 → Q7 兜底 → 01_身份与角色（学生身份）
2. 选专业的原因是"觉得好找工作" → Q5 价值判断 → 02_价值观与信念（实用主义倾向）
3. 大学四年"平淡"——用户对大学经历的评价 → Q6 观察 → 03_底层思维模式（自我评价偏低调）
4. 室友小李，大学最好的朋友 → Q1 是人 → 05_人际关系网络
5. 小李性格开朗，用户安静——互补型朋友 → 补充到 05 小李的档案
6. 小李对用户有带动作用（社团、实习） → 补充到 05 小李的档案
7. 毕业后小李去深圳，用户在武汉，联系变少 → 补充到 05 小李的档案
```

### 第三步：检查已有文件

- 05_人际关系网络/ 下还没有 小李 的文件 → 新建
- 01_身份与角色/ 下可能已有其他身份文件 → 新建 `大学生.md` 或更新已有身份文件
- 02_价值观与信念 写入待归纳区

### 第四步：新建子文件

**新建 `05_人际关系网络/小李_大学室友.md`：**
```markdown
# 小李 · 大学室友

## 核心信息

- 大学室友，大学时期最好的朋友
- 同在武汉某二本读市场营销专业
- 性格开朗外向，用户形容"在人群里最活跃的人"
- 与用户性格互补（用户偏安静内向）
- 对用户有带动作用：拉着用户参加社团、面试实习
- 毕业后小李去了深圳，用户留在武汉，联系减少但仍保持每年过年问候

## 相关链接

- [[武汉某二本]]
- [[市场营销]]

## 元信息

- 记录时间：2026-07-13
- 信息来源：对话
```

**新建 `01_身份与角色/大学生.md`（如果尚无）：**
```markdown
# 大学生

## 核心信息

- 就读于武汉某二本，市场营销专业
- 高考成绩一般，选专业主要考虑就业前景
- 大学四年自评"平淡"
- 大学期间受室友小李影响，参加了社团和实习

## 相关链接

- [[小李_大学室友]]
- [[武汉某二本]]

## 元信息

- 记录时间：2026-07-13
- 信息来源：对话
```

### 第五步：更新总文件

**更新 `05_人际关系网络/人际关系网络.md`：**
```markdown
# 05_人际关系网络

## 索引

- [[小李_大学室友]]
```

**更新 `01_身份与角色/身份与角色.md`：**
```markdown
# 01_身份与角色

## 索引

- [[大学生]]
```

### 第六步：建立双向链接

```
05_人际关系网络/小李_大学室友.md
├── [[武汉某二本]]
└── [[市场营销]]

01_身份与角色/大学生.md
├── [[小李_大学室友]]
├── [[武汉某二本]]
```

### 第七步：更新 user_index.md

在 user_index.md 对应区域添加：
```markdown
- [05_人际关系网络/小李_大学室友](05_人际关系网络/小李_大学室友.md)
- [01_身份与角色/大学生](01_身份与角色/大学生.md)
```

### 第八步：更新 user_log.md

```markdown

**沉淀内容：**
- [05_人际关系网络] [[小李_大学室友]] - 大学室友，最好的朋友，性格互补
- [01_身份与角色] [[大学生]] - 武汉某二本市场营销专业

**关联建立：**
```

## 示例二：多维度交叉

### 对话片段

```
用户：2020 年我和张三一起创业，那时候我刚从上一家公司离职。
      我们做了一个 B 端 SaaS 产品，我负责产品和客户，他负责技术。
      那两年我学到了很多东西，尤其是谈判——以前我完全不会跟客户谈价格。
      但也挺累的，经常凌晨还在改方案。最后因为资金链断了，2022 年关掉了。
      不过我不后悔，那是我成长最快的一段经历。
```

### 提取与归类

```
1. 2020年离职创业 → Q3 过去重大转折 → 06_人生重大轨迹
2. 合伙人张三 → Q1 是人 → 05_人际关系网络
3. B 端 SaaS 产品 → Q7 兜底 → 01_身份与角色（创业者）
4. 学会了谈判技巧 → Q4 技能 → 04_技能与特长
5. 资金链断裂 2022 年关闭 → 补充到 06 创业经历
6. "不后悔"、认为"成长最快" → Q5 价值判断 → 02_价值观与信念（待归纳区）
7. "经常凌晨还在改方案" → Q6 观察 → 03_底层思维模式（待观察：愿意为事业付出高强度努力）
```

### 需要建立/更新的文件

| 文件 | 操作 | 维度 |
|------|------|------|
| `2020_创业经历.md` | 新建 | 06_人生重大轨迹 |
| `张三_创业伙伴.md` | 新建 | 05_人际关系网络 |
| `创业者.md` | 新建或更新 | 01_身份与角色 |
| `谈判技巧.md` | 新建 | 04_技能与特长 |
| `02_价值观与信念.md` | 更新待归纳区 | 02_价值观与信念 |
| `03_底层思维模式.md` | 更新观察记录区 | 03_底层思维模式 |

### 双向链接结构

```
05_人际关系网络/张三_创业伙伴.md
├── 内容提到 [[2020_创业经历]]
└── 内容提到 [[谈判技巧]]

06_人生重大轨迹/2020_创业经历.md
├── 内容提到 [[张三_创业伙伴]]
├── 内容提到 [[谈判技巧]]
└── 内容提到 [[创业者]]

04_技能与特长/谈判技巧.md
├── 内容提到 [[张三_创业伙伴]]
└── 内容提到 [[2020_创业经历]]

01_身份与角色/创业者.md
└── 内容提到 [[2020_创业经历]]

02_价值观与信念/价值观与信念.md（待归纳区）
└── 2026-07-13: "不后悔创业，那是我成长最快的一段经历"——过程比结果重要

03_底层思维模式/底层思维模式.md（观察记录区）
└── 2026-07-13: 创业期间经常凌晨改方案——愿意为目标付出高强度努力
```

## 示例三：更新已有文件

### 场景

用户之前已经聊过张三（已有 `张三_创业伙伴.md`），这次又提到了关于张三的新信息。

### 对话片段

```
用户：后来张三去了字节跳动做技术经理，我们偶尔还会约饭聊聊行业动态。
```

### 处理方式

**不是新建文件**，而是**更新已有文件** `张三_创业伙伴.md`，追加：

```markdown
## 近况更新（2026-07-13）

- 张三目前在某互联网公司担任技术经理
- 与用户仍保持联系，偶尔约饭聊行业
```

同时更新 user_log.md：
```markdown
## 2026-07-13 16:00

**已有文件更新：**
- [05_人际关系网络] [[张三_创业伙伴]] - 补充近况：现于字节跳动任技术经理

**关联建立：**
- [[张三_创业伙伴]] ↔ [[某互联网公司]]
```

## 示例四：价值观待归纳

### 场景

多次对话中，用户反复表达了相似的价值判断。

### 待归纳区积累

```
待归纳区：
- 2026-06-20: "我觉得自由比稳定重要，不想被一份工作绑住"
- 2026-07-03: 谈到朋友进了体制内，用户说"那种生活不适合我"
- 2026-07-13: 聊到创业失败，用户说"至少我试过了，比待在舒适区强"
```

### 触发归纳

3 条以上相似判断 → 提示用户：

> "我发现你多次提到自由、不愿被束缚、宁可冒险尝试也不愿待在舒适区。这是否可以归纳为一条核心价值观——「自由与探索优先于稳定」？"

用户确认后：
1. 新建 `02_价值观与信念/自由与探索优先于稳定.md`
2. 将 3 条待归纳记录移入子文件
3. 清空待归纳区的这 3 条

## 常见错误与纠正

| 错误 | 问题 | 纠正 |
|------|------|------|
| 在总文件里写完整内容 | 违反每信息一文件原则 | 建独立子文件，总文件只放链接 |
| 忘记建立双向链接 | A 链接了 B，B 没链接回 A | 逐对检查，确保双向 |
| 过度抽象用户原话 | "用户经历了职业转变" vs 原话"我受不了天天坐办公室" | 保留原话的具体性和情绪 |
| 把技能写成身份 | `产品经理.md` 放到了 04_技能 | 移到 01_身份与角色 |
| 把信念写成事实 | "用户是自由职业者"（事实）当作价值观 | 事实放 01，价值判断放 02 |
| 信息归属选择有误 | 把"刚换工作"放到了 06（应该放 07） | 用决策树重新判断 |
